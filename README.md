# Бесплатный сканер Binance Futures MACD(12,26,9) → Telegram

Мониторит **все активные USDⓈ-M фьючерсы с `quoteAsset=USDT`** на `5m` и `15m`. Каждые ~5 минут получает 210 свечей каждой пары, вычисляет **именно MACD Line = EMA(close,12) − EMA(close,26)**, а не её пересечение с Signal Line. Уведомляет только после закрытия свечи. Никаких сделок не открывает.

> **Важно:** стандартный сервер GitHub Actions может иметь IP-адрес в регионе, где Binance Futures недоступен (HTTP 451). Это ограничение нельзя исправить настройками скрипта. GitHub Actions также допускает задержки и пропуск некоторых запусков; поэтому оповещения не имеют гарантии доставки строго через 5 минут. См. «Ограничения» ниже.

## Состав проекта

- `scanner.py` — готовый сканер; Python 3.12, **без сторонних библиотек**.
- `.github/workflows/macd-alerts.yml` — запуск каждые 5 минут и сохранение состояния.
- `tests/test_scanner.py` — локальные тесты расчёта MACD и оповещений.
- `.gitignore` — исключает рабочее состояние и секреты.

## Шаг 1. Создайте Telegram-бота

1. В Telegram откройте **@BotFather** и отправьте `/newbot`.
2. Сохраните выданный `BOT_TOKEN` (строго конфиденциально).
3. Откройте созданного бота и отправьте ему `/start`.
4. Получите свой chat ID: в адресной строке браузера откройте `https://api.telegram.org/botВАШ_ТОКЕН/getUpdates`, найдите `message.chat.id`. **Не публикуйте ссылку с токеном**; она содержит ваш секрет.

## Шаг 2. Создайте репозиторий GitHub

1. Войдите на https://github.com и создайте репозиторий, например `binance-macd-alerts`.
2. Укажите **Public**. Стандартные GitHub-hosted Actions runner в публичных репозиториях бесплатны. В приватном репозитории 5-минутный мониторинг может превысить включённый лимит минут.
3. Загрузите содержимое **папки** проекта в корень репозитория. Должны получиться `scanner.py`, `.github/workflows/macd-alerts.yml`, `tests/test_scanner.py`. GitHub Web Upload иногда не позволяет загрузить скрытую папку `.github`; при необходимости создайте файл через GitHub → **Add file → Create new file**, набрав путь `.github/workflows/macd-alerts.yml`, вставьте содержимое.
4. На вкладке **Settings → Secrets and variables → Actions → New repository secret** создайте два секрета **ровно** с названиями:

   - `TELEGRAM_BOT_TOKEN` = токен от BotFather.
   - `TELEGRAM_CHAT_ID` = число `message.chat.id` из getUpdates.

5. Перейдите во вкладку **Actions → MACD Zero Line Scanner → Run workflow**. Оставьте `reset_state` выключенным (это действие для аварийного сброса истории). После завершения откройте лог `Scan MACD and send Telegram alerts`.
6. На первом успешном запуске в Telegram придёт служебное сообщение о синхронизации. Сигналы начнут приходить **со следующей закрытой свечи**, пересёкшей ноль.
7. По расписанию сценарий будет запускаться автоматически каждые 5 минут. Чтобы проверить, во вкладке Actions должны появляться новые запуски.

## Условия сигнала

- **LONG**: на предыдущей **закрытой** свече MACD Line `<=0`, на текущей закрытой свече `>0`.
- **SHORT**: на предыдущей **закрытой** свече MACD Line `>=0`, на текущей закрытой свече `<0`.
- **В настройках:** EMA fast=12, slow=26, signal=9. Signal EMA считается, но **не используется как условие входа**.
- Анализируются цены закрытия **обычных фьючерсных свечей**, а не mark price.
- Работа со свечой в процессе формирования исключена. Значения MACD приблизительно совпадают с TradingView; из-за конечных 210 свечей у нуля возможна малая погрешность против EMA на всей истории.

## Предотвращение дублей

После успешного отправления всех уведомлений скрипт обновляет `.state/state.json`. Workflow прикладывает этот файл как артефакт `macd-state` (2 дня хранения). На следующем запуске GitHub CLI восстанавливает последнее успешное состояние. Для каждой пары и таймфрейма хранится **время последней проверенной закрытой свечи**. Старые свечи повторно не проверяются. `concurrency` не даёт двум workflow отправлять оповещения одновременно; при очереди GitHub может заменять ожидающие запуски, но скрипт просматривает несколько предыдущих закрытых свечей.

**Гарантия не абсолютная:** если Telegram принял первые сообщения пачки, но отклонил последующие, а выполнение не дошло до сохранения артефакта, следующий запуск может повторить уже доставленные сообщения. Это сознательный выбор «не терять сигналы при ошибке отправки», а не ложное обещание exactly-once. Также при задержке дольше окна в 210 свечей история за его пределами может быть пропущена.

## Защита от лимитов API

- В среднем не более **7 запросов/с**, максимум **8 параллельных потоков**.
- Запросы свечей: `limit=210`, стоимость **2 Binance weight** за запрос согласно документации.
- Пауза и повтор на `429`, ограниченные повторы на временных `5xx` и сетевых ошибках.
- Немедленный останов на `418` (бан IP) и `451` (региональная блокировка).
- Публичные endpoint-ы — **ключ Binance не нужен**.
- Не рекомендуется запускать ещё несколько идентичных копий этого workflow одновременно с одного IP.

## Ограничения и диагностика

- `HTTP 451`: GitHub runner или ваша сеть находится в недоступной для Binance Futures юрисдикции. **Этот вариант через стандартный GitHub-hosted runner в данном регионе не будет работать**. Понадобится разрешённая инфраструктура с доступом к API; код сохраняется.
- `HTTP 429`: превышен IP-вес запросов (возможен даже при ограничении скрипта на разделяемом IP). Понизьте `BINANCE_REQUESTS_PER_SECOND` с `7` до `4` и/или число параллельных потоков; затем повторите.
- `403 / chat not found`: проверьте токен и chat_id, отправьте боту `/start`.
- Нет сигналов после запуска: это нормально, пока закрытые MACD-свечи не пересекают ноль. Первое сообщение служебное.
- Ошибка `checkpoint is missing`: состояние последнего успешного запуска не удалось получить. Проверьте права Actions, существующие артефакты и историю запусков. При сознательном сбросе можно запустить workflow вручную с `reset_state=true` — старые сигналы не восстанавливаются.
- Нет периодических запусков: GitHub может задерживать/пропускать scheduled workflow; на публичных репозиториях расписание **отключается после 60 дней без активности**. Может потребоваться изменить расписание в репозитории, чтобы возобновить.
- На публичном GitHub код открыт для всех, но `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` хранятся в Secrets (не публикуйте их в файлах/логах).
- Запуски за `5m` с полным набором монет могут затянуться; не следует считать, что сигнал появляется сразу на границе свечи. Для гарантированных быстрых оповещений нужен постоянно работающий процесс.

**Нормативные источники:** GitHub Actions schedule/billing/artifacts; Binance USDⓈ-M `/fapi/v1/klines`, `/fapi/v1/exchangeInfo`; Telegram Bot API (см. ссылки в сопроводительном ответе).
